## 4. Severity Rationale

- **High** findings either hide a documented-but-broken command (TG-01), let survivorship or post-formation data pass the suite (TG-04, TG-06), let replays mutate history (TG-07), or leave the suite unable to prove SQL runs (TG-16) and unable to measure itself (TG-14).
- **Medium** findings pin wrong defaults, omit control/boundary/calendar/label/macro/determinism tests, or leave entry points unexecuted.
- **Low** findings are convention and precision issues with no current leakage path.

## 5. Limits

- No coverage percentage is reported: installing coverage tooling would be a config change, out of scope for this audit stage.
- The Stage 1A 22-file/398-test targeted set was not reconstructed; Stage 1C ran a new 16-file set (302 passed) chosen for the gap areas.
- Live-DB tests depend on warehouse state; the run proves they execute, not that they are hermetic.
